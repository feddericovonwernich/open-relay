02 / lens ledger

Six boundaries define one review path.

Each lens lists trusted inputs, one invariant, one result, and one failure boundary. Each failure boundary keeps unrelated work active.

Lens 01

Evidence

The connector gets the authoritative review state once. It bounds the state and creates a digest.

Owned inputs
Repository mode, reviewer logins, current head, GraphQL review-thread pages, and configured provider root authors.
Invariant
GitHub supplies the resolution state. isResolved and the root author determine the evidence. Comment bodies are untrusted data.
Emitted result
The connector emits a bounded evidence snapshot. The snapshot includes deterministic pagination, counts, and a canonical digest.
Failure boundary
An error in GraphQL, pagination, truncation, or identity mapping stops unified verification for this path. Low-level events continue.

Lens 02

Decisions

Fixed rules map raw checks and findings to a fixed action set.

Owned inputs
Terminal Check Runs, unresolved configured-provider threads, and normalized Bugbot conclusions.
Invariant
verdict = actions.length === 0 ? success : action_required. The same evidence always produces one verdict.
Emitted result
The connector emits a deterministic verdict and ordered actions. Each action identifies a CI failure, an unresolved finding, or an ambiguous neutral result.
Failure boundary
Malformed or ambiguous mappings stop unified verification for this path. Configured automation and generic CI events continue.

Lens 03

Settlement

The connector creates a notification only from stable evidence for the current head.

Owned inputs
Verdict, canonical payload identity, observed commit head, continuous observation state, and one-shot mode.
Invariant
Continuous mode requires two identical eligible observations. A changed head resets the observation. The connector checks the final head before emission.
Emitted result
The connector emits one action-required or success notification for an accepted identity. Process state prevents replay of that identity.
Failure boundary
Head drift, pending CI, or a transient evidence error delays or stops settlement. Low-level event production continues.

Lens 04

Delivery

The notification worker prints before it completes the event.

Owned inputs
The worker receives one Relay event for one correlation. relay notify hides registration and leasing. The worker prints to stdout.
Invariant
The print succeeds before completion. Delivery is at least once. The worker must not lose an event silently.
Emitted result
The worker prints one JSON line to stdout. It then completes the event.
Failure boundary
A crash before completion leaves the event available for lease expiry and replay. Registration and leasing remain outside the worker path.

Single-consumer notification delivery

Lens 05

Resilience

Failures remain in the repository or path that owns them.

Owned inputs
Connector authentication, repository verification paths, GraphQL responses, Relay availability, and head observations.
Invariant
An authentication failure stops the connector. Other failures remain repository- or path-scoped. They do not stop sibling work.
Emitted result
Low-level events continue. Relay retries eligible delivery. Isolated paths report or delay only their own result.
Failure boundary
GraphQL errors, invalid mappings, Relay outages, and head drift stop only the affected unified path. Configured automation and generic CI events continue.

Failure isolation and retry

Lens 06

Future aggregation

The first producer includes a boundary for a future reducer. It does not include the reducer.

Owned inputs
Correlated low-level events and the existing generic notification delivery contract.
Invariant
The design does not add a projection engine before a second use case exists. A migration must preserve or version producer and idempotency rules.
Emitted result
A future typed durable reducer can consume the event family. It can reuse notification delivery. The current watcher does not emit a projection.
Failure boundary
A future aggregation failure cannot change connector-owned facts or the generic delivery contract.
