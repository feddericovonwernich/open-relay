The proposition

Borrow the relay.
Open the vocabulary.

Impeccable proves the transport pattern. Our change is to replace hard-coded event dispatch with a versioned registry and two explicit execution adapters.

Keep fixed

Local helper, browser POST, SSE feedback, long-poll agent pickup, durable journal, and HMR-friendly source ownership.

Make extensible

Event names, input and output schemas, timeouts, retry limits, instructions, and executable commands.

Refuse

Distributed workers, fan-out topics, workflow DAGs, exactly-once side effects, and in-process third-party code.

Transport, identity, and endpoint topology

Behavior is versioned.
Meaning is immutable.

At acceptance, the relay hashes the complete resolved definition and stores that revision on the event. Reloading the registry cannot change queued work; changing semantics requires a new version.

Reviewed event lifecycle

State and history commit together.

BEGIN IMMEDIATE;

SELECT id FROM events
WHERE (
    state = 'queued'
    OR (state = 'retry_wait'
        AND available_at <= :now)
  )
  AND definition_revision IN :workerCaps
ORDER BY created_at
LIMIT 1;

UPDATE events SET
  state = 'leased',
  attempt = attempt + 1,
  worker_id = :worker,
  lease_id = :lease,
  lease_expires_at = :deadline
WHERE id = :id;

INSERT INTO updates
  (event_id, kind, attempt, worker_id, lease_id)
VALUES
  (:id, 'leased', :attempt, :worker, :lease);

COMMIT;

Atomic lease and journal transaction

Two adapters.
One guarded contract.

handler.kind = agent

Registered harness

  • Registers workerId, allowed agent definitions, tools, structured-output support, token limits, and concurrency.
  • External long-poll can lease only handler.kind = agent; process work stays internal.
  • A concurrent control long-poll aborts model and tool signals when cancellation arrives.
  • Every renew, progress, cancellation acknowledgement, and settlement proves both worker and lease identity.
worker credential → capability match → scoped lease → validated result
handler.kind = process

Relay-owned subprocess

  • A relay-owned process loop acquires only process definitions; plugins never poll the queue.
  • Immutable delivery enters through stdin; bounded JSONL leaves through stdout.
  • Protocol violation, cancellation, and timeout all trigger TERM, grace period, then KILL.
  • Trusted local code receives an allow-listed environment and project-root working directory.
spawn without shell → bounded stdio → effect evidence → atomic settle
Guarded handler adapters

Context is assembled by trust level.

1 · SYSTEM

Immutable harness policy: safety, secret handling, effect rules, and forbidden actions.

2 · DEFINITION

Content-addressed project instructions and output contract. May narrow tools, never expand system policy.

3 · CONTEXT

Retrieved files and documents carry provenance, byte counts, and explicit untrusted-data delimiters.

4 · PAYLOAD

Schema-valid does not mean trusted. Producer text cannot change policy or capabilities.

5 · OUTPUT

Model output is untrusted until schema, lease, effect evidence, and tool-policy checks pass.

Reviewed executable-plugin dataflow

Retries stop where effects begin.

1 · CLASSIFY

Policy

Definition declares retry-safe, idempotency-required, or manual-recovery.

2 · INTEND

Effect key

Persist event ID plus deterministic operation key before acting.

3 · EXECUTE

External call

Pass the key downstream where supported; renew the lease while active.

4 · CONFIRM

Evidence

Persist external reference or explicit proof that no effect occurred.

5 · SETTLE

Decision

Complete, retry later, cancel, or stop in recovery_required.

retry-safeNo durable external effect. Relay may schedule another attempt with backoff.
idempotency-requiredRetry after expiry only when persisted intent proves the downstream system enforces the deterministic effect key.
manual-recoveryUnknown outcome never retries automatically; an operator inspects evidence and resolves state.
Effect safety and recovery policy

Persist first.
Fence every transition.

Acceptance, acquisition, retry, cancellation, recovery, and terminal settlement all mutate canonical state and append their ordered update in one transaction.

01 · ACCEPT

Deduplicate

Resolve producer and key; validate payload; bind immutable definition revision.

02 · COMMIT

Queue

Insert event and queued update atomically; replayed key returns the same ID.

03 · MATCH

Lease

Select a compatible worker; commit worker, lease, attempt, deadline, and update.

04 · EXECUTE

Evidence

Assemble trusted context, enforce tools, renew, and record consequential effects.

05 · SETTLE

Resolve

Validate output and evidence; complete, retry_wait, cancel, fail, or require recovery.

Reviewed delivery sequence

Notifications wake.
The cursor catches up.

#104

queued — event and update committed together.

#105

leased — worker, lease, attempt, and deadline recorded.

#106

progress — current worker and lease verified.

#107

retry_scheduled — cause and available_at persisted.

#108

completed — state and terminal evidence committed.

Gap-free cursor protocol

  1. Register a sequence-aware wake buffer before reading state.
  2. Read canonical state and high-water mark H in one SQLite read transaction.
  3. With a retained cursor, emit rows (cursor, H] and advance per row; without one, emit a canonical snapshot tagged H and set cursor = H.
  4. Query sequence > cursor, emit in order, advance the cursor, and deduplicate by sequence until caught up.
  5. Wait for notification or heartbeat, then query again. The in-memory signal never carries correctness.

A missed wake costs latency.
A durable row cannot be missed.

Reviewed failure and recovery matrix

Ownership is split by failure domain.

PRODUCER AUTHOR

Meaning

  • Use a scoped producer credential.
  • Generate a stable idempotency key before POST.
  • Retry a lost response with the same key.
  • Treat SSE as observation, not completion authority.
DEFINITION AUTHOR

Contract

  • Version every semantic change.
  • Declare capabilities and token budgets.
  • Choose effect and retry policy.
  • Keep schemas and instructions deterministic.
HANDLER AUTHOR

Effects

  • Treat payload and retrieved context as untrusted.
  • Deduplicate effects by event ID.
  • Renew within the hard deadline.
  • Return structured evidence, never retry policy.
RELAY OWNER

Reliability

  • Scope producer, observer, worker, and admin credentials.
  • Commit state and journal together.
  • Fence worker and lease identity.
  • Stop uncertain effects in recovery.
Local does not mean unauthenticated. Bind to loopback; issue role-scoped boot credentials; allow configured browser origins; keep secrets out of events; resolve definition paths beneath project root; spawn without a shell; cap request, context, stdout, stderr, progress, and result sizes.

Reviewed implementation plan

Open behavior.
Closed invariants.

Extensibility controls meaning and execution. Identity, immutable definitions, trust, effects, recovery, and delivery correctness remain relay-owned.

  1. Acceptance invariantOne producer and idempotency key resolve to one event and immutable definition revision.
  2. Transition invariantCanonical state and its ordered update commit or roll back together.
  3. Authority invariantOnly the capability-matched worker holding the current lease may mutate delivery state.
  4. Effect invariantUnproven consequential work never retries when its external outcome is unknown.
  5. Context invariantUntrusted data cannot expand tools or policy; resolved secrets are redacted before model reuse or persistence.
  6. Observation invariantEvery SSE client catches up from durable sequence rows; notifications carry no correctness.
First milestone: one accepted intent survives every retry boundary.

Only after acceptance, journal, lease, effect, and recovery invariants hold do agent and process adapters join the system.
